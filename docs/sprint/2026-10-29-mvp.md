## 1. Decision

**Product council.**

**MVP sentence:** A product manager submits one build-or-not claim and the evidence on both sides, and ProofGraph runs the existing propose-then-check path so one real verdict comes back — SUPPORTED, CONTRADICTED, or UNRESOLVED — with the supporting links, the contradicting links, what is still unresolved, and the sources those links used.

That is the product in `docs/01-product-brief.md`: check every link, trust the weakest one. It is not advice, a chatbot, or a RAG app. Decision D28 says the product is the general checker and freight is one example packet. A product-decision claim is that generality, shown on the same path as every other text case.

Thursday 29 is already this loop. The exit in `docs/12-sprint-manager.md` is a live Streamlit action that runs propose and the engine on the detention/legal-hours claim and shows the verdict and the reasons, not a stored verdict. The upload path (`input_file`, no `File id:` line) stays with its owner. The full numeric run stays stopped. This MVP does not open a new product. It gives that same check a lead story that is not logistics, plus the packet shape the three new branches share.

The system does not tell the PM what to ship. It checks the factual links the decision rests on and leaves the unstated "should" visible as unresolved or assumed.

**Lead case, so the three branches do not invent three claims.**

| | |
|---|---|
| Case id | `ship-export-this-week` |
| Statement | We should ship the export button this week. Weekly use is 40%, and the support cost is $1,000 a month. |
| Supports | A usage note: export is used by 40% of weekly active accounts. |
| Contradicts | A support note: export support costs $4,200 a month. |

`world` on the packet wrapper is `product decision`. `Case.dataset` is `freight` because this is a built-by-us demonstration, the same rule `docs/05-datasets-and-eval.md` already applies to the governing-law packet. It is not a benchmark. `mode` is `passage`.

## 2. Value

**Product council.** One segment for this demo. The product still serves people who sign off on document conclusions (billing reviewers, auditors, contract reviewers). Today the person at the screen is a PM who must decide whether to build something while holding notes that disagree.

| | |
|---|---|
| Who | A product manager under time pressure, with a usage note, a cost note, and a release note that do not say the same thing. |
| Why | Decide what to build or not build without a contrary figure disappearing into one confident summary. |
| What before | Reread the notes, or ask a model that cites a real line and still drops the other side. Direct Muse is the named alternative (decision D26). A spreadsheet is the other. |
| How | One claim, the packet, then the existing proposer and engine. The screen keeps the passing link, the failing link, and the gap. |
| What after | After one run they can point to the 40% line that holds, the $4,200 line that breaks the $1,000 claim, and the release note that does not settle "this week." They could not see that split, tied to source text and to an executed check, before the run. |
| Alternatives | A model that answers the claim in one breath. It is faster and it hides the weak link. ProofGraph is the check before that answer is trusted. |

**Hypothesis this demo tests:** one domain-general path is enough for a product decision and for a second world. If the engine needs a product-specific branch, the demo fails.

**Two other domains the corpus may include.** The engine does not grow a branch for either.

1. **Filings.** `examples/packets/numeric-val-0.json`. World `SEC filing`. `dataset` stays `findver`. The claim is the Ryman net-interest sentence. Gold stays on `answer` / `expected`, never in the prompt.
2. **Contracts.** `examples/packets/late-fee-overcharge.json`. World `contract late fee`. `dataset` stays `freight`. A 1.5% late charge on $10,000 is $150, and the invoice says $500. `governing-law-not-mentioned.json` is the wording gap (Delaware is not in the clause). It is not ContractNLI.

Logistics stays a corpus row and Thursday's live claim (`The invoice detention charge of $450.00 is correct.`). It is not the lead story and not a special engine.

**Today's metric:** a judge can score the section 5 checklist yes after one run. That is the one metric for this day. The North Star stays the one in the product brief: fewer wrongly approved claims than a direct model answer, on the benchmarks, when those runs are allowed. This sprint does not claim that result.

## 3. Journey

**Product council.** Persona: a PM deciding whether the export button ships this week. The job is to see both sides before they commit. Awareness, signup, and advocacy are outside this day.

| Step | What they do | Touchpoint | What they are asking | Where it hurts |
|---|---|---|---|---|
| 1. State the claim | Paste the ship-or-not statement | Claim field | "Will the other side survive?" | A freight-only form that will not accept this sentence |
| 2. Attach both sides | Add the usage note, the cost note, and the release note as text | Evidence items | "Does the cost note stay in the packet?" | A single summary box that merges the notes |
| 3. Run | Press the check | The existing button | "Is this actually checking?" | A stamp that appears with no engine call |
| 4. Read the split | See support, contradiction, and the gap | Result | "What held, what broke, what is open?" | Only the word CONTRADICTED, with the 40% line gone |
| 5. Open the source | Read the quote in the note it came from | Source text | "Can I check the citation?" | A reason with no source id and no text |

**Moment of value.** Step 4, when the 40% line is still on screen next to the $4,200 contradiction and the release note is visibly unsettled. That is the aha. The stamp alone is not the value. If they only see a verdict word, they are back to the model summary they already had.

**Story the UI implements.** As a product manager deciding what to build, I want to submit one claim and the notes on both sides, so that I can see what supports it, what contradicts it, and what is still unresolved before I decide.

The detention reviewer journey stays. `live_case()` and the Thursday button keep the detention claim. Tests in `tests/test_app.py` lock that claim and the current story strings. The PM case is a second packet on the same screen, not a replacement.

## 4. Technical fit

**Technical lead.** This is what `b3a9429` actually runs.

There is no `verify()`. The path that exists is `propose` then `run_program`. `app/streamlit_app.py` `check_claim` already does that, and it calls `for_engine` first so `answer` and `gold_evidence` are cleared. `proofgraph/__main__.py` and `tests/test_packets.py` call `run_program` on a fixture program with no network. Architecture's `pipeline.verify` includes the objection loop. That file is not in this tree. Do not add it today. A live objection round is a "nice" row after the five musts, not this exit.

`engine/ground.py` quote-matches `Source.text` only. It does not call text-in-box, `blind_reread`, or `sam_count`. Those functions exist (`proofgraph/pdf.py`, `proofgraph/clients/checker.py`, `proofgraph/clients/sam.py`) and are not on this path. The PM packet is text. Friday's boxed bundle is a different exit. Do not block this demo on it.

A PDF or image source with `text` empty will not ground. `propose` can still attach it as `input_file` (`proofgraph/propose.py`). The quote check then returns ungrounded. The text packet is the seam that works today.

| Journey step | Module | Already true | Thinnest seam still missing |
|---|---|---|---|
| State the claim | `Case.claim` in `proofgraph/schema.py`. `check_claim` and `_upload_case` in `app/streamlit_app.py`. | Any string is a legal claim. The wired example is the detention fixture via `live_case()`. | The PM sentence as `case.claim` on a packet the screen can load. No new field. |

| Run | `proofgraph/propose.py` `propose`. `proofgraph/engine/route.py` `run_program`. `check_claim`. | Propose returns a `ClaimProgram`. The engine grounds, checks, and combines. `tests/test_app.py` proves an empty program does not reuse the detention verdict. | Offline test for `ship-export-this-week` with no paid call. Live button keeps `check_claim`. |
| Check each link | `engine/ground.py`, `engine/calc.py`, `engine/route.py` `check`, `clients/checker.py` `blind_wording`. | Quote match, calculator, wording, assumed rule with a null expr. | None for a text compute packet. Wording on the release note needs the checker; the offline test does not call it. Put "this week" in `unverifiable_parts` or a non-required gap so the gap is visible without a paid call. |
| One verdict | `engine/combine.py` | One of SUPPORTED, CONTRADICTED, UNRESOLVED, plus label, reasons, reason codes, fact checks, link results. A failing required link returns CONTRADICTED and still keeps earlier unverifiable reasons. Passing links stay on `link_results`. | UI groups those statuses. It does not invent a second verdict. |

**How the three panes map onto one verdict.** Support is a `link_results` status `pass` (and the grounded quotes that fed it). Contradiction is status `fail`. Unresolved is `blocked`, `not_mentioned`, an ungrounded fact, `unverifiable_parts`, or a reason code. The stamp is the one `verdict`. Empty panes are honest. A second stamp is not.

## 5. Acceptance bar

**Hackathon judge.** Watch one run of `ship-export-this-week`. Score yes or no. A no on any line fails the demo.

**Scenario the judge is watching.**

- Starting state: the lead packet is loaded from the repo. The engine has not been shown `expected`, `answer`, or `gold_evidence`. The offline test has already run with no network. The watched run uses the same function.
- Role: the judge, on the PM's claim.
- Steps: read the statement, see three notes, run the check, read the stamp, the two sides, the gap, and a source quote.

| # | Yes only if |
|---|---|
| 1 | The verdict is produced by `run_program` (offline) or by `check_claim` (propose, then `run_program`). A written-in stamp, or a replay of `expected`, is a no. |
| 2 | Support is visible: at least one link status `pass`, with the quote it used. |
| 3 | Contradiction is visible: at least one link status `fail`, with the quote it used. |
| 4 | Something unresolved is visible: the release-note gap, an unverifiable part, a `blocked` or `not_mentioned` link, or a reason code. It is not a third verdict. |
| 5 | Each cited source shows its id and its text. |
| 6 | This product-decision claim completes on that path. |
| 7 | A second domain would use the same path: `late-fee-overcharge` or `numeric-val-0` goes through the same function with no product-specific or freight-specific branch. |
| 8 | No answer-key cheating. The prompt and the engine input omit `expected`, `answer`, `gold_evidence`, and FinDVer leak fields. The UI does not paint `expected`. |
| 9 | An offline test runs this packet through `run_program` with no network and no new dependency. `tests/test_packets.py` is the pattern. |

Changing the proposed program must be able to change the verdict. `tests/test_app.py` already shows an empty program on the detention claim comes back UNRESOLVED. The lead packet's offline test has to assert the engine result, not a constant.

**Land in this order.**

1. **Corpus first.** Both code owners need one file. Until `examples/packets/ship-export-this-week.json` exists, the engine test and the screen have nothing shared to load.
2. **Engine second.** The offline test pins `verdict`, `label`, link statuses, and the unresolved signal from `run_program`. That pin is the contract the UI asserts against.
3. **UI last.** It loads that file, calls the same function, and shows those strings.

**How to tell the UI and the engine agree.** Same path, same packet. The UI test reads `Verdict` from `run_program` (offline) or `check_claim` (fake client). Visible verdict, label, reasons, and link statuses equal that object. The test fails if the screen reads `expected` or `answer`. `late-fee-overcharge.json` through the same function, with no new branch, is the second-domain check.
